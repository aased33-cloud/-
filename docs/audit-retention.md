# 변경 이력 6개월 자동 정리

관리자가 지정한 보관 정책: 매일 실행해 실행 시각 기준 **6개월보다 오래된** `audit_log` 행만 삭제한다. 정확히 6개월인 행은 다음 실행까지 유지한다. 직원 계정, 근태, 휴일근무, 설정은 삭제 대상이 아니다. 하루 한 번 실행하므로 실제 삭제는 기준 시각 이후 다음 실행 때 이루어진다.

이 문서는 설정 안내이며 예약 작업을 자동 생성하거나 운영 데이터에 접근하지 않는다. 최초 실행 시 이미 6개월을 지난 이력도 삭제된다. 운영 활성화 전에 관리자에게 영향과 예상 삭제 범위를 안내하고, 필요한 이력을 내려받거나 복원 가능한 백업을 확보한다.

## 별도의 Render Cron Job 구성 (운영 반영 검토 후)

- 기존 웹 서비스와는 별도 서비스로 만든다. Git 저장소는 기존 프로젝트, 브랜치는 검증 후 확정된 운영 브랜치를 사용한다.
- 런타임: Node. 빌드 명령: `npm ci`. 실행 명령: `node cleanup-audit.js`.
- 예약: `0 18 * * *` (UTC 18:00, 한국시간 매일 03:00).
- 해당 예약 서비스의 환경 변수에 데이터베이스 연결 정보 `DATABASE_URL`과 `AUDIT_RETENTION_DELETE_ENABLED=true`를 안전하게 설정한다. 값을 저장소·로그에 쓰지 않는다. `PGSSL=disable`은 운영에 사용하지 않는다.
- 연결 정보는 운영 웹 서비스의 DB와 같은 대상인지 확인하고 테스트 환경과 혼동하지 않는다. 운영 적용 전에는 반드시 별도 테스트 DB로 검증한다.
- Render Cron Job에는 별도 비용이 발생할 수 있다. 생성 전에 현재 요금을 확인한다. 작업 실패 알림과 로그를 확인하고 정상 실행 여부를 주기적으로 점검한다. 실행 실패나 일시 중지 시 정리가 늦어질 수 있다.
- 중단하려면 예약 작업을 일시 중지하거나 예약 서비스의 `AUDIT_RETENTION_DELETE_ENABLED`를 `true` 이외로 바꾼다. 웹 서비스의 환경 설정은 변경하지 않는다.

스크립트는 환경 변수가 명시적으로 `true`가 아니면 DB에 연결하지 않는다. 예약 서비스 생성이나 활성화만으로 변경된 웹 코드가 배포되는 것은 아니며, 웹 서비스는 별도 배포 절차가 필요하다.
