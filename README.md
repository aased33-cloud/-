# 근태 통합관리

## 현재 상태
실제 PostgreSQL 데이터베이스와 서버 세션을 사용하는 웹 애플리케이션입니다. Supabase 연결 정보와 운영 호스팅은 아직 연결되지 않았으며, 연결 및 검증 전에는 실제 운영 서비스를 제공하지 않습니다. 사번·이름만을 통한 가입/재설정은 본인 확인이 아니며 사칭 위험이 큽니다. 특히 관리자 계정에 대해서는 운영 전에 별도의 안전한 본인 확인 방식이 강력히 권장됩니다.

## 실행
Node.js 20 이상, PostgreSQL, 지속 실행이 가능한 Node 호스팅이 필요합니다. Supabase에서 프로젝트와 전용 DB 접근 계정, TLS가 적용된 연결 문자열을 준비합니다. 연결 문자열은 서버 환경 변수에만 보관합니다.

```sh
npm ci
export DATABASE_URL='postgresql://...'
export SESSION_SECRET='충분히 긴 무작위 비밀값'
export NODE_ENV=production
node setup.js employees.csv
npm start
```

로컬 PostgreSQL에 TLS가 없으면 로컬에 한해서 `PGSSL=disable`을 설정합니다. 운영 환경은 HTTPS와 TLS 검증을 사용합니다. 리버스 프록시는 `X-Forwarded-Proto`를 신뢰할 수 있도록 구성해야 합니다. 외부에서 데이터베이스 테이블에 직접 접근하지 않도록 권한 및 방화벽을 설정합니다. 데이터베이스 로그인 권한은 앱이 사용하는 테이블에만 부여하세요. `SESSION_SECRET`은 최소 32바이트 이상 무작위 값으로 설정해야 합니다.

직원 엑셀 파일을 UTF-8 CSV로 저장하고 `사번,이름,권한` 열 순서를 사용합니다. 권한은 `관리자` 또는 `직원`입니다. 사번의 앞자리 0이 사라지지 않도록 엑셀에서 텍스트 형식으로 설정합니다. 최초 등록은 빈 DB에서만 가능하며 관리자 한 명 이상이 필요합니다. CSV는 평문 직원 정보이므로 안전하게 전달하고 사용 후 삭제합니다.

초기 DB 설정은 DDL 권한이 있는 별도의 관리자 접속으로 실행하고, 웹 서버는 필요한 테이블만 접근 가능한 전용 계정으로 실행하세요. 월 1회 백업 및 1년 보관은 서비스의 요금제와 별도 자동화 설정이 필요하며 아직 구현·연결되지 않았습니다. 월별 복구 테스트와 암호화 보관, 보관 만료 삭제를 설정해야 합니다.
